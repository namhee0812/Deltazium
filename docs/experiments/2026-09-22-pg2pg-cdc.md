# PostgreSQL 소스 → PostgreSQL 타깃 CDC 검증 (2026-09-22)

- 대상: Deltazium main(6fab34c) — backend 8090, Connect 8083(Debezium 3.6.0.Final,
  Iceberg sink 1.12.0-SNAPSHOT)
- 소스: PostgreSQL 15.3(`wal_level=logical`), topic_prefix `nhtest`
- 타깃: PostgreSQL 15.3(별도 인스턴스)
- 목적: 지금까지 실 배선 검증이 없었던 **PostgreSQL 타깃** 경로(데이터면 + 제어면)를 확인.
  리포 코드·기존 등록/커넥터/커넥션은 검증 중 수정하지 않았다.

## 결론

- **데이터 경로(스냅샷 → DML upsert/delete → changelog)는 PG 타깃에서도 행 단위로
  정확히 동작했다.** 초기 30/60건, DML 후 45/80건, DDL 후 47건 모두 정렬 덤프 diff 0.
- **제어면의 타깃 식별자 정규화가 PG 타깃을 깨뜨렸다.** 등록 시 타깃 스키마·테이블명을
  DbType과 무관하게 대문자로 저장하는 것이 원인 — JDBC sink는 unquoted 식별자라 PostgreSQL이
  소문자로 접어 우연히 동작했지만, DDL 승인 초안은 따옴표를 쳐서 **승인이
  `schema "CDC_TMP" does not exist`(HTTP 502)로 실패**했다(결함 D1). 등록 이벤트 키도
  같은 이유로 대문자 강제라 테이블 drawer 이벤트 목록에서 누락됐다(결함 D2).
  두 결함은 `feature/pg-target-identifier`에서 수정 — 상세는 `docs/internals.md`
  "PG 타깃 식별자 폴딩 — D1·D2 수정" 절, 규칙은 `docs/architecture.md` 8절.

  (`CDC_TMP.ORDERS`) — 커넥터 4종(source·jdbc-sink×2·iceberg-sink)은 전부 RUNNING으로
  배포됐다(D1 발견 지점, 아직 이땐 증상 없음 — unquoted라 우연히 동작) |
| 초기 스냅샷 | 성공 | notification 토픽 STARTED→COMPLETED, 타깃 30/60건, 정렬 덤프 diff 0 |
| DML 혼합 | 성공 | orders/items INSERT·UPDATE·DELETE 혼합 트랜잭션 4건, 약 2초 내 타깃 반영,
  타깃 45/80건, 전체 행 diff 0(삭제 행 잔존 0, UPDATE 값 반영 확인) |

  추가)까지 architecture.md 5절 스키마와 일치. 불일치 2건: 등록 이벤트 키 대소문자(D2),

  backend 재기동 전까지 poller가 구독하지 않음) |
| DDL(ADD COLUMN) | **부분 실패** | 소스 `ALTER TABLE ... ADD COLUMN note` 직후 sink task가

  포함 행 반영·diff 0 확인 |

## 발견 결함

### D1 — PG 타깃 DDL 승인 실패 (타깃 식별자 대문자 정규화 + 따옴표 초안)
등록 시 타깃 스키마·테이블명을 DbType과 무관하게 대문자로 저장하는 코드가 원인. JDBC
sink는 unquoted 실행이라 PostgreSQL이 소문자로 접어 우연히 동작하지만, DDL 승인 초안은
따옴표를 쳐서 그 문자열 그대로 식별자가 된다 — 존재하지 않는 대문자 스키마를 찾아 502.
Oracle 타깃은 대문자가 정답이라 드러나지 않았다. 영향: PostgreSQL 타깃의 DDL 승인 워크플로
(architecture.md 7절) 전체 불능. `feature/pg-target-identifier`에서 수정(`DbType.
foldIdentifier`로 타깃 DbType 기준 폴딩).

### D2 — 등록 이벤트가 대문자 키로 저장돼 테이블 drawer에서 누락
D1과 같은 코드 경로가 등록 이벤트 키도 대문자로 강제. 다른 기록처(DDL 승인·커넥터 상태
모니터)는 원문 키를 쓰므로 같은 테이블인데 이벤트 종류별로 키가 갈라져 UI 정확 일치 필터에서
REGISTERED 이벤트가 누락됐다. `feature/pg-target-identifier`에서 수정.

### D3 — 새로 등록한 소스의 스냅샷 진행이 UI에 안 보임 (기존 한계, 재확인)
notification 토픽에는 STARTED→COMPLETED가 전부 기록되는데 `/api/capture/snapshot`은
`phase=NONE`. `docs/internals.md`에 이미 기록된 한계(poller가 `@PostConstruct` 시점
SOURCE 커넥션 목록으로만 구독, 새 소스는 backend 재기동 필요) — 이번 검증은 backend를
재기동하지 않았으므로 재현된 것뿐, 새 결함 아님.

### 정보 (결함 아님)
- `schema.evolution=none`이라 소스 ALTER 직후 sink task가 FAILED로 떨어지는 것은 의도된
  게이트 — "장애 → 승인 → 재시도" 운영 절차와 일치.
- Iceberg changelog의 `source` struct에는 소스 DbType별 필드(Oracle: scn, PostgreSQL: lsn·
  xmin·txId)가 함께 있다 — architecture.md 5절 고정 스키마 + evolve-schema로 정상.

## 남겨 둔 상태

검증에 쓴 커넥션·등록·커넥터·Kafka 토픽·Iceberg changelog·소스/타깃 스키마 객체는 검증
